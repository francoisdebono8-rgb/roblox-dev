# PresetForge 2.0 real-project validation

Read-only inspection completed 2026-09-25 in under 15 minutes total. All three local copies use the MIT license; no upstream content was copied or modified.

| Project | Evidence inspected | Does 2.0 address the observed work? |
| --- | --- | --- |
| `Roblox/resources` at `ee51421` | 1,222 files, 50 `SetAttribute` calls, 87 tag API calls, authored UI/effect/configuration assets mixed with code-generated behavior. | **Partly.** Exact attribute/tag recipes, controlled non-BasePart schemas, and auditable filtering help with authored instances. Many setups are generated by Luau and are better maintained in code, so PresetForge should not replace those factories. |
| `TheNexusAvenger/Nexus-Battles` at `fd6505c` | Large checked-in models: 15,119 Parts, 130 MeshParts, 91 supported lights, 21 Sounds, 8 ParticleEmitters, and 65 Decals. | **Yes.** Exact fields, descendant class/name/tag filters, per-object diffs, result selection, and shared Project recipes directly reduce repetitive map and asset normalization while making the blast radius visible. |
| `jblaz6335/hacker-tycoon` at `a71871c` | 71 files and 201 `Instance.new` calls; the world is primarily assembled at runtime by service/build scripts rather than checked-in Studio assets. | **Rarely.** PresetForge can help isolated authored UI or effects, but code factories are the correct source of truth for the dominant workflow. A broader arbitrary editor would not improve this project. |

## Verdict

The 2.0 workflow addresses the previously observed repetitive work in two of three projects, most strongly in the large authored map corpus. The negative case remains important: PresetForge is valuable for repeated Studio authoring, not runtime-generated architecture. The controlled schema, filtered scope, diff, project recipes, and one-step Undo form the paid-product boundary; stacks, search/favorites, cloud, AI, and arbitrary property support remain unsupported because this corpus did not justify them.
