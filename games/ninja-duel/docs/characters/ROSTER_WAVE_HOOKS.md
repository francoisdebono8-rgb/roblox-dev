## Détail minimal par hook

- **H01** : tables `STANCE/GAIT/CLIPS/MELEE/intro/aura/castSpec/BUILD/styles d'impact` indexées par `fighterId` **sans repli Minato** (défaut neutre sans arme) ; boucles sur `CLIPS` entier ; liste jouable lue dans les données ; costume `World.dress` par fighter. Déclencheur concret d'ARC-002 : `VelmoraMotionEngine.luau` fait 1 820 lignes pour 4 fighters → découper les **données** de clips par fighter (pas de framework).
- **H02** : `def.String` (liste de noms d'`Attacks`) + `Combo.next` par acteur ; `Attacks` par fighter (`Light4`, coups propres) ; règles de combo scaling inchangées (`Config.ComboScaling`).
- **H03** : indices déclaratifs par technique (`Ai={min,max,on,chance}`) + profil par fighter (distance, signature à rechercher) ; garder l'IA sur les mêmes coûts et fenêtres que le joueur (AI-001).
- **H17** : `def.Substitution={Mode,…}`, `def.PerfectDodge`, `def.Rush`, `MoveGraphs.disengage` comme clés d'une table de handlers ; migrer seal/crow de CORE4 sans changer leur comportement.
- **H04** : pile de modificateurs par acteur (source, durée, vitesse/accélération/esquive/saut) lue par `Place1Movement` **et** `Motor.step` ; ne jamais muter `a.def` (partagé, cf. duels miroirs). Mesurer d'abord l'écrêtage actuel (régression CORE4).
- **H05** : coût en PV non létal (plancher 1, comme `HealthDrain`), drain/s d'état, transfert `victime → lanceur`, surcharge au-delà du max avec décroissance, sursaut 1×/manche ; affichage HUD.
- **H09** : `a.stance` + `def.Stances[nom]` qui surcharge profil, routes et champs (`Sharingan`) ; action `TechniqueRelease` côté entrée pour les paliers de maintien (lisibles, interruptibles).
- **H06** : zone `{kind, owner, forme (disque/couloir orienté), durée, effets}` : dégâts, modificateur H04, force vectorielle, bonus propriétaire, activation (« sur sable », « sur eau »), relais ; rendu client par `kind` ; nettoyage par `Combat:clear`.
- **H07** : table de règles `nature × zone/objet → résultat` évaluée aux points existants (`projectileHit/Surface`, entrée en zone) ; commencer par **une** règle visible (vent × feu ou foudre × métal), puis étendre (TOOL-006).
- **H08** : volume d'interception attaché à une action active → `destroy | reflect | absorb | redirect` ; un projectile dévié est **tué puis recréé** (le client ne sait pas courber une trajectoire), comme ricochet et Geometry.
- **H10** : lien `a.controlledBy` avec règles de sortie (substitution à coût, interruption du lanceur) ; possession = intention de mouvement imposée en miroir, arbitrée avec l'IA et (plus tard) suspendue dans la prédiction client (NET-001).
- **H11** : dossier `match.terrain` **inclus** dans les raycasts, PV, résistance par nature, `NinjaWall` (splat + course), empreinte d'ombre, limite par propriétaire, nettoyage ; casse par mêlée (volume Bangla) et projectiles.
- **H13** : drapeau `armor` sur une fenêtre d'attaque : légers encaissés (dégâts, pas de réaction), cassée par lourds/launchers/saisies/techniques et par l'attaque `pierce` (Kakashi) ; coût éventuel par coup absorbé.
- **H12** : `c.entities` (non-acteurs, 1 PV, durée, comportements scriptés : aller vers, frapper une fois, imiter avec retard, tenir) ; coups jugés depuis l'entité (`hitOrigin`) ; projectiles et volumes de mêlée testés contre elles ; liste `entities` du snapshot ; rendu client (rig + costume du propriétaire) ; v0 = entités visuelles non touchables (reflets, clones de route).
- **H15** : projectile à pas dirigé côté serveur (virage max/s, collé au sol) répliqué par points de passage.
- **H14** : saisie autorisée en l'air dans une fenêtre de route + projection plongeante (base : relocation du LionBarrage, `Brawler.luau:224-236`).
- **H16** : audit « portable » de chaque module de technique (pas de lecture de `a.def` d'origine) + liste blanche ; mêmes coûts/CD que l'original, modulés.
