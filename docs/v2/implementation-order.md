# Proposed Forge V2 implementation order

Decision date: 2026-09-27. Issue #15 first block is audit/design only. **Stop here:
no production code changes or public updates are authorized by this block.**

Inputs: [baseline](catalog-baseline.md), [research](research-evidence.md),
[Studio execution](studio-audit-evidence.md), [design system](forge-design-system.md).
Five products remain frozen. Preserve all five canonical IDs, including AccessForge's
canonical rather than its accidental duplicate.

## Decision, not a fabricated market score

There is no product-level sales winner: the accessible incoming transaction view was
empty and public reviews were zero for all five. Search positions measure visibility
only. Order therefore weighs reproduced friction, external request fit, competitive
substitution and the ability to demonstrate a meaningful improvement.

| Order | Product | Why this position | First bounded scope |
|---:|---|---|---|
| 1 | [PresetForge](../../products/presetforge/v2/AUDIT.md) | Broad repeated configuration workflow; direct request revived in 2026; reproducible clipped editor and noisy changes review. Existing engine already works. | Responsive recipe/target/change flow, changes-first review and affected-object locating; then bounded recipe search/duplicate parity. |
| 2 | [SchemaForge](../../products/schemaforge/v2/AUDIT.md) | Recent designer-context request and a distinct saved-contract/child-rule workflow; current UI hides context. Strong competition means improve comprehension, not add a spreadsheet. | Compact contract header, expected/actual/note findings, subset selection, stable rule editing. |
| 3 | [CurveForge](../../products/curveforge/v2/AUDIT.md) | Real repetition need and highly demonstrable spatial edit; poor isolated Preview reproduced. Free alternatives narrow the paid case. | Contextual Preview, top-level existing-output edit, clear ordered control feedback. |
| 4 | [AccessForge](../../products/accessforge/v2/AUDIT.md) | Serious responsive/stale-state friction and clear factory scenario, but no strong fresh outreach and ordinary stairs are well served free. | Fix dock/state clarity, endpoint locating/reassignment and contextual fitting. No new generator. |
| 5 | [JointForge](../../products/jointforge/v2/AUDIT.md) | Same-name endpoint ambiguity is real; diagnostics can help, but basic creation/pivot editing have strong native/free substitutes and the fresh tool request is runtime-oriented. | Endpoint identity/locating, concise broken/conflict findings, clear errors. No animation/rigging expansion. |

This is not ordered by code size or age. AccessForge has acute layout friction, but
its weaker acquisition evidence argues against a large generator expansion. JointForge
is last because its commercial gap is narrower, not because its implementation is old.
Reassess if actual buyer feedback arrives; do not force equal engineering budgets.

## First implementation recommendation

**PresetForge first**, as a bounded UX-led iteration on its already-shipped 2.0.0 engine.
It has the most direct reusable-configuration request and an immediately reproduced
failure of discoverability. Prove that a user can capture, target, review and apply in
a normal dock before adding scope. Use a new semantic version appropriate to the actual
change; "catalogue V2" must not silently reuse package version 2.0.0.

The first pass establishes a tested interaction pattern, not a generic UI framework.
Only extract a shared component once SchemaForge or another product needs the same one.
This is a recommendation for the next execution block, not an implementation performed.

## Rejected programme creep

- Product 6, a bundle manager, launcher, cloud accounts or telemetry.
- Universal property reflection, arbitrary scripting recipes, recipe stack conflict systems.
- Runtime grip injection, animation/auto-rigging or destructive endpoint auto-repair.
- Roads/terrain/cities, hollow extrusion, obstacle routing or decorative generator catalogues.
- Automatic configuration correctness, destructive type conversion and hierarchy auto-repair.
- Renaming/recreating public assets to reset metrics; duplicate V2 assets.
- Pretending existing tags, per-field selection, schema notes or Undo are newly invented.
- Replacing missing sales/impression data with estimated conversion or forum-like counts.

## Gate for subsequent execution

One product at a time: approve a narrow scope, implement against the existing engine,
test exact final artifact in Studio, run the realistic new/existing workflow and native
Undo/Redo, prepare three honest media shots, then update only its canonical asset when
publication is authorized. Recheck current competitors/outreach first. Record the same
baseline signals after relaunch; do not claim causal sales uplift from one observation.

The PresetForge/JointForge real-project commercial media plans still show pending in
the current repository. Today's audit did not complete those historical capture tasks.
Address them with the eventual product relaunch, without claiming they were already done.
